Edge TLS / reachability synthetics per tenant (`model_backend_monitors/cert_monitors.tf`), motivated by the 2026-08-04 EEOC onboarding incident: the beta-stack rollout generated the beta cert (`api.beta.<tenant>...`) but NOT the production certs for `chat.<tenant>.usai.gov` / `console.<tenant>.usai.gov`, so client TLS failed with a wrong/missing-cert error and nothing alerted — the gap was found only by a live incident call. Three checks, created per host for every tenant: (1) an SSL synthetic (`datadog_synthetics_test` subtype `ssl`) asserting the served cert is valid, hostname/SAN-matched, and has >14 days left — fires on missing/wrong/untrusted/expiring cert, the exact EEOC failure; (2) an HTTP synthetic asserting a 2xx/3xx status over valid TLS — also catches the network/allowlist drop the same client hit; (3) a `cert_expiry` metric monitor on the SSL test's `synthetics.ssl.days_left`, warning at 45d / critical at 14d so a slowly-expiring cert is caught with time to rotate (ACM generation + PR is not instant). **Gated OFF by default** (`enable_edge_synthetics = false`, empty `synthetic_locations`) and creates zero resources until enabled — because the edge WAF's default-BLOCK + GSA/Zscaler allowlist (the very allowlist the EEOC client tripped) would silently block Datadog's public synthetic-location IPs, making public-location tests fail forever. Enabling requires a Datadog **private location** provisioned in allowlisted egress and its range added to the WAF allowlist; only then set `enable_edge_synthetics = true` + `synthetic_locations = ["pl:..."]` per tenant. Hostnames default to the slug (`chat`/`console.<tenant>.usai.gov`), overridable via `edge_hosts` for tenants whose naming differs. Validated against the live gov Datadog API by test-applying to eeoc (then destroying): this caught three schema errors `terraform validate` cannot (gov-only location `aws:us-gov-west-1`; `statusCode` requires `is`/`isNot` not range operators; monitor query threshold must equal the *critical* value) — all fixed — and empirically confirmed the WAF caveat: public-location synthetics timed out (the same silent perimeter-drop the client hit), proving the private-location requirement is real, not speculative. Also includes an **UNVERIFIED, separately-gated** ACM cert-expiry metric monitor (`enable_acm_cert_monitor`, default false) intended as an always-on expiry backstop that needs no private location (uses `aws.certificatemanager.days_to_expiry`, confirmed live on gsa/doc). It is NOT ready: in testing it stayed `No Data` for ~6 min despite the metric being queryable, root cause unresolved (likely sparse-metric monitor-eval latency); it was applied then destroyed and must be re-tested on one tenant for 15-20 min before rollout (`notify_no_data=true` would false-page otherwise). Kept in-tree, clearly marked, rather than lost. `terraform validate` clean; `plan` adds 0 resources (everything gated off by default).
