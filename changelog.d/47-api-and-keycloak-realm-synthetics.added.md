API-host and Keycloak-realm synthetics for every tenant, generalising two coverage gaps that existed in exactly one org each. Found on 2026-08-19 while auditing the hand-built UI tests left over from the `<tenant>.usai.gov` cutover: **ftc** alone had `API Health Monitor` + `API SSL Certificate` on `api.ftc.usai.gov`, and **doj** alone had a `Keycloak Realm Monitor` on `auth.usai.gov/realms/doj` — both covering dependencies that every tenant shares. Adds (1) `api.<label>.usai.gov` to `local.edge_hosts`, so the API host inherits `ssl_cert`, `https_reach` and `ssl_cert_expiring_soon` automatically — it was previously unmonitored everywhere despite being the host the chat frontend calls server-side; (2) an `api_health` synthetic on `api.<label>.usai.gov/health` asserting `200` and `$.status contains true`, kept as its own resource rather than folded into `edge_health` because the API's contract differs on **both** axes (path `/health` vs `/healthz`, body `{"status":true}` vs `{"status":"healthy"}` — verified across all 15 enabled tenants); and (3) a `keycloak_realm` synthetic per tenant on `auth.usai.gov/realms/<label>`, asserting `200` **and** `$.realm` equals the expected realm — a bare `200` would not catch a misrouted realm, since Keycloak answers with `200` + JSON for *any* realm that exists. **The Keycloak check is gated separately and defaults on for all 25 tenants**, unlike the edge synthetics: its target is shared aigov infrastructure, not the tenant's own edge, so the per-tenant WAF reachability that blocks 8 tenants (`dnfsb doj faa nrc ntsb oge nsf eeoc`, see #44) does not apply. The evidence is doj itself — one of those 8, whose hand-built version of this test kept passing from the public `aws:us-gov-west-1` location for the entire period its edge was unreachable. That means the 8 tenants which can have **no edge monitoring at all**, plus `doli` and `ang` which aren't serving, now at least have login-path coverage: 25 realm tests vs 15 edge-gated ones. Realms were verified to exist and return a matching name for all 25 — which surfaced that **doli's realm is `dol`, not `doli`** (`/realms/doli` is a 404, `/realms/dol` returns 200), so `edge_domain_label = "dol"` is now set explicitly on doli; the realm probe keys off `local.edge_label` precisely so slug≠label tenants resolve correctly, and setting the label is safe while `enable_edge_synthetics = false` because it only corrects the name without creating an edge test. Documents an important operational caveat on `api_health`: `api.<label>/health` emits **sporadic `503 upstream connect error`** — measured at roughly 1-in-3 on hhs across two separate samples, with opm showing an isolated 503 — while the apex `/healthz` reports `checks.api: healthy` throughout, because the frontend reaches the API over an internal URL rather than this public host. The `retry(2)` + `min_failure_duration(300s)` pairing is therefore **load-bearing rather than boilerplate**: a run fails only if all three attempts fail and the monitor pages only after 5 continuous minutes of failed runs, so that blip rate cannot page while a genuinely dead upstream still does. The in-file comment says not to loosen either value, and warns against reading the monitor as proof the API is 100% healthy — partial 5xx rates are an envoy/ingress-rate question, not a black-box up/down one. Also re-verifies both deliberate opt-outs after the platform-wide cutover: `doli` did **not** come along (`dol.usai.gov` and `doli.usai.gov` still fail to resolve, `chat.dol`/`console.dol` return 404) and `ang` is still undeployed (`ang.usai.gov` still 503).
