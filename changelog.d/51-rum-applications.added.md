Per-tenant Datadog **RUM application** (`modules/model_backend_monitors/rum.tf`, `type = "browser"`, named `usai-<tenant>`), plus a root-level `rum_credentials` output (`terraform/outputs.tf`) exposing `{ application_id, client_token }` keyed by tenant slug for all 25 enabled tenants. The RUM app must exist in each tenant's own Datadog org before the browser SDK can ship real-user data, and the two values the SDK needs are only knowable *after* create — so they're surfaced as an output for syncing into each tenant's frontend env vars rather than hand-copied out of the Datadog UI. `client_token` is a write-only ingest identifier, not a secret (it ships in the browser bundle by design), so the output is deliberately **not** marked `sensitive` — that keeps `terraform output -json rum_credentials` usable for the env-var sync. First non-monitor/non-dashboard resource class in this repo; note that the tenant list in `outputs.tf` is hand-maintained for the same reason `tenants.tf` is (providers can't take `for_each`), so onboarding a tenant now means adding it in both files.
