Edge synthetics now target the post-rename tenant hostnames, fixing health checks that had been failing across 10 orgs. The 2026-08 tenant move to `<agency>.usai.gov` is a **three-part** change and each part alone breaks a naive health check: (1) **host** — `chat.<label>.usai.gov` now `301`-redirects to the bare apex `<label>.usai.gov`, so a test without `follow_redirects` fails `statusCode is 200` on the redirect itself; (2) **path** — `/health` is gone, and on the apex it returns `404` with the SPA's HTML, so following the redirect does *not* rescue a `/health` test (it must be `/healthz`); (3) **body** — the old payload was `{"status":true}` and the apex returns `{"status":"healthy","timestamp":...,"checks":{"cache":...,"api":...}}`, so a `$.status contains true` assertion fails against `"healthy"`. The module's `edge_hosts` default therefore changes from `chat.<tenant>.usai.gov` + `console.<tenant>.usai.gov` to `<label>.usai.gov` + `console.<label>.usai.gov`. Verified against live DNS/TLS on 2026-08-18: `https://<label>.usai.gov/healthz` returns `200 {"status":"healthy"}` on **all 23 reachable tenants** — including tenants whose `chat.` host had not yet been cut over (`doi ed fhfa ftc hhs doj faa` still served `chat.` directly at the time) — so the apex is safe to target uniformly and needs no per-tenant migration flag or dual-host tolerance logic. `console.<label>` and `api.<label>` were **not** renamed and still return `200`, so only the `chat.` → apex collapse mattered. Adds a new `edge_health` HTTP synthetic per tenant on `<label>.usai.gov/healthz` asserting `200` **and** a `healthy` status body — the body assertion matters because `/healthz` aggregates the app's own `cache` and upstream-`api` dependency checks, which is exactly the signal the 2026-08-13 stateoig outage needed and the readiness probe missed. The check is **apex-only on purpose**: `/healthz` is not a universal path (`console.<label>` `302`s it to a login callback, the API host `404`s it and still serves `/health` returning `{"status":true}`), so iterating `edge_hosts` here would have created a guaranteed-failing console test; console/API liveness stays covered by the existing `https_reach` test asserting `200` on `/`. Adds `var.edge_domain_label` because the tenant slug is **not** always the DNS label — `doli` publishes at `chat.dol.usai.gov` (label `dol`), which a slug-derived host would have silently monitored as a name that does not resolve. `follow_redirects = true` on the health check is defensive rather than load-bearing (the apex serves `/healthz` directly today) but is precisely what the replaced tests lacked when `chat.<label>` started redirecting.
