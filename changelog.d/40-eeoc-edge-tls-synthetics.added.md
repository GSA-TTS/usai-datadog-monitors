Edge TLS / reachability synthetics per tenant (`model_backend_monitors/cert_monitors.tf`), motivated by the 2026-08-04 EEOC onboarding incident: the beta-stack rollout generated the beta cert (`api.beta.<tenant>...`) but NOT the production certs for `chat.<tenant>.usai.gov` / `console.<tenant>.usai.gov`, so client TLS failed with a wrong/missing-cert error and nothing alerted — the gap was found only by a live incident call. Three checks, created per host for every tenant: (1) an SSL synthetic (`datadog_synthetics_test` subtype `ssl`) asserting the served cert is trusted and has more than 14 days left — a missing/expired/untrusted/self-signed cert fails the run at connection time, which is the EEOC failure; (2) an HTTP synthetic that follows redirects and asserts a final `200` over valid TLS — this is also what covers the hostname/SAN-mismatch case (an HTTP client rejects a name-mismatched cert, whereas Datadog's SSL-test docs confirm expiry/trust failures but do not document SAN verification), and it catches the network/allowlist drop the same client hit; (3) a second SSL synthetic asserting more than 45 days remaining, deliberately handle-less, so a slowly-expiring cert surfaces as a ticket with time to rotate (ACM generation + a PR is not instant). Both paging checks re-notify daily (`renotify_interval = 1440`) since a broken cert stays broken until someone rotates it. **Gated OFF by default** (`enable_edge_synthetics = false`, empty `synthetic_locations`) and creates zero resources until enabled — because the edge WAF's default-BLOCK + GSA/Zscaler allowlist (the very allowlist the EEOC client tripped) would silently block Datadog's public synthetic-location IPs, making public-location tests fail forever. Enabling requires a Datadog **private location** provisioned in allowlisted egress and its range added to the WAF allowlist; only then set `enable_edge_synthetics = true` + `synthetic_locations = ["pl:..."]` per tenant. Hostnames default to the slug (`chat`/`console.<tenant>.usai.gov` — both patterns verified to resolve in DNS for gsa and doc), overridable via `edge_hosts` for tenants whose naming differs. Validated against the live gov Datadog API by test-applying to eeoc (then destroying): this caught three schema errors `terraform validate` cannot (gov-only location `aws:us-gov-west-1`; `statusCode` requires `is`/`isNot` not range operators; monitor query threshold must equal the *critical* value) — all fixed — and empirically confirmed the WAF caveat: public-location synthetics timed out (the same silent perimeter-drop the client hit), proving the private-location requirement is real, not speculative. The 45-day tier was originally a `datadog_monitor` querying `synthetics.ssl.days_left`, which **does not exist**: code review plus a live API check confirmed `GET /api/v1/metrics/synthetics.ssl.days_left` returns `not found`, while `synthetics.ssl.time_to_expiry` exists and is denominated in **minutes** (so `< 14` would have meant 14 minutes, not 14 days). With `notify_no_data = false` that monitor would have sat in No Data indefinitely while displaying green — strictly worse than the original gap, and not something a test-apply can catch, since Datadog accepts a monitor on any metric name and simply parks it. Replaced with the second SSL synthetic described above, which reuses the one assertion form the provider documents and removes the metric-name, unit, and `check_id`-tag uncertainty in a single move. Cert thresholds are bound to shared locals (`cert_expiry_warn_days` / `cert_expiry_crit_days` in `locals.tf`) per the #33 no-drift rule. Also includes an **UNVERIFIED, separately-gated** ACM cert-expiry metric monitor (`enable_acm_cert_monitor`, default false) intended as an always-on expiry backstop that needs no private location (uses `aws.certificatemanager.days_to_expiry`, confirmed live on gsa/doc). It is NOT ready: in testing it stayed `No Data` for ~6 min despite the metric being queryable, root cause unresolved (likely sparse-metric monitor-eval latency). It now ships with `notify_no_data = false` so a premature enable is silent rather than a 25-org false page — flipping that to `true` is an explicit step in the in-file verification checklist — and it must be re-tested on one tenant for 15-20 min before rollout. Kept in-tree, clearly marked, rather than lost. `terraform validate` clean; `plan` adds 0 resources (everything is gated off by default, and the root module wires none of the new variables, so the feature is unreachable without an explicit per-tenant opt-in).
