**The 45-day cert-expiry tier now pages, and re-pages daily**, and TLS cert checks are deduplicated to the apex host. Two changes to the same monitor family. **(1) The 45-day tier shipped handle-less** on the reasoning that "a cert 45 days out is a ticket, not a page" — the repo's usual convention that warn tiers don't page. In practice no ticket ever existed: `ed` and `gsa` both reached **18 days** to expiry with their alerts sitting in Datadog seen by nobody, because a handle-less monitor notifies no one and nothing else was watching the queue. A deliberately-quiet tier turned out to be indistinguishable from no monitoring at all. It now carries `${var.notification_channel}` scoped to `{{#is_alert}}` / `{{#is_alert_recovery}}` and sets `renotify_interval = 1440`. This is a considered reversal of the warn-tier convention rather than an oversight, and the justification is that this is not really a warn tier — it is the *only comfortable* window to act in. By the time the 14-day tier fires, ACM issuance plus a PR is already tight; renewing at 45 days is routine, renewing at 14 is an incident. Daily repetition is the point, since an expiring cert stays expiring until someone acts, so a single missed page means it lapses. The alert body now also states that the one certificate covers apex, console and api, so the reader knows a single renewal fixes all three. **(2) Cert checks are apex-only** (new `local.cert_hosts`, overridable via `var.cert_hosts`). `ssl_cert` and `ssl_cert_expiring_soon` previously iterated every host in `local.edge_hosts`, producing 3 + 3 tests per tenant that all watched **the same certificate** — verified on 2026-08-19 by comparing cert serials across apex, console and api for all 15 enabled tenants, identical in every single case, because one ACM cert carries all the names (e.g. `ed`'s SANs are `api.ed.usai.gov, console.ed.usai.gov, chat.ed.usai.gov, ed.usai.gov`). The duplication was not harmless: when `ed`, `gsa` and `opm` crossed the 45-day line they each produced **three identical expiry alerts for one renewal action**, which would have tripled the page volume the moment this tier started paging. Coverage is unchanged — a missing, expired, untrusted, self-signed or wrong-name certificate is caught exactly as before, since it is one cert object. Per-host **reachability** is untouched: `https_reach` still runs on apex, console and api, because those front genuinely different backends. `var.cert_hosts` exists for the case where a tenant is ever issued a *separate* cert for api or console; the documented check is comparing `openssl s_client -connect <host>:443 -servername <host> | openssl x509 -noout -serial` per host. Net effect: 60 destroyed (30 `ssl_cert` + 30 `ssl_cert_expiring_soon`, all of them the console and api instances — the apex tests are updated in place, never recreated), 15 updated, 0 added. Total synthetics 190 → 130, with one daily-paging expiry alert per tenant instead of three silent ones.
